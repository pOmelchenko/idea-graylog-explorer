# Graylog Explorer — плагин JetBrains

Независимый плагин для PhpStorm / IntelliJ IDEA **2026.3**. Интерфейс использует
дерево подключений и streams, таблицу событий и панель подробностей. Версия 0.12.0.

## Установка

1. Собрать проект или взять `build/distributions/graylog-jetbrains-0.12.0.zip`.
2. В IDE открыть **Settings → Plugins → ⚙ → Install Plugin from Disk…**.
3. Выбрать ZIP. Перезапустить IDE, если она предложит это сделать.
4. Открыть **View → Tool Windows → Graylog**.
5. Нажать **+**, указать имя, API URL и токен Graylog.

API URL: например, `https://graylog.example.org/api`. Можно указать адрес
за reverse proxy: `https://example.org/graylog/api`. Если `/api` отсутствует,
плагин добавит его. Web URL задаётся отдельно, когда веб-интерфейс и API находятся
на разных адресах.

Токен создаётся в Graylog: **System → Users and Teams → More → Edit tokens**.
Он передаётся как HTTP Basic `TOKEN:token`. Плагин сохраняет токен в Password Safe
IDE. Серверы и общие параметры сохраняются на уровне IDE, пути, формат логов
и поиски — в локальном workspace проекта.
При редактировании подключения пустое поле токена сохраняет прежнее значение.

## Возможности

Компоновка следует Git Log в IDE: общие действия находятся в узкой вертикальной
полосе слева, над деревом есть поиск по подключениям и streams, над таблицей —
одна строка запроса с компактными фильтрами периода и размера страницы.
Запуск поиска: Enter/Ctrl+Enter или лупа в строке запроса. Управление подключениями
и Settings доступны в компактной левой полосе; Live и Code marks находятся рядом
с фильтрами поиска. Названия действий показаны в подсказках. Фильтрация дерева
сохраняет текущую выборку логов и индекс. Дерево использует нативное выделение
JetBrains для всей строки, с фокусом и без фокуса.

Вертикальный тулбар использует штатные размеры и отступы платформы без mini-режима;
у дерева есть отдельная левая граница, а поиск оформлен `SearchFieldWithExtension`,
как в Git Log. Верхняя стрелка скрывает и возвращает дерево подключений; состояние
сохраняется для проекта. Expand/Collapse раскрывают дерево, сохраняя активный stream,
запрос, загруженную страницу и полный индекс исключений.
Шестерёнка открывает меню общих и проектных настроек.

В дереве выбранного подключения есть группа **Sources** с цветами, счётчиками и
флажками. Клик по строке или Space/Enter переключает источник; несколько выбранных
источников объединяются через OR. **All sources** снимает фильтр. При этом выбранный
stream, базовый запрос и временные границы сохраняются, а таблица и полный индекс
исключений получают один и тот же фильтр. Поиск слева находит также имена источников,
не меняя запрос логов. Свёрнутая вручную группа остаётся свёрнутой после обновления.

Список относится к выполненному поиску, его stream и периоду; имя stream видно
рядом с **Sources**. Серверная агрегация запускается после успешного поиска, даже
если отдельное окно не открывали. Она исключает собственный фильтр sources, поэтому
после выбора одного сервиса в дереве остаются остальные. Количество ограничено 1000
значений с явной отметкой; при ошибке показаны только источники загруженной страницы
с соответствующей подписью. Выбранные вручную имена сохраняются даже вне списка.
Кнопка **Refresh streams and sources** обновляет обе группы.

Фильтр **Sources** рядом с периодом получает значения и число сообщений серверной
агрегацией за весь период, stream и текстовый запрос, независимо от страницы логов
и готовности индекса исключений. Внутри списка доступны поиск по имени и выбор
нескольких источников. Выбранные значения объединяются через OR, затем через AND
с текстовым запросом; скобки и экранирование сохраняют исходный смысл запроса.
Окно использует штатный перемещаемый и изменяемый popup JetBrains: его можно
перетаскивать за заголовок, менять размер за край; размер сохраняется для проекта.
Минимальный размер оставляет доступными поиск и кнопки. В таблице **Source / Messages**
клик по заголовку переключает сортировку, число сообщений сортируется численно.
Сортировка, поиск и Refresh сохраняют черновой выбор; **Cancel** его отбрасывает.
Дерево и окно управляют одним фильтром. Фильтр действует на таблицу, пагинацию и полный индекс исключений. Текст запроса
остаётся отдельным. Apply применяет выбор, Cancel его отбрасывает, All sources
снимает фильтр. Контекстное меню строки содержит Only this source и Add to source filter.

Список загружается после поиска или по открытию фильтра и кэшируется на 30 секунд для той же области
поиска. Агрегация выполняется без собственного фильтра sources, поэтому после выбора
одного сервиса остаётся возможность добавить другие. При большой кардинальности
показываются до 1000 значений с явной отметкой ограничения. Если имя отсутствует,
его можно ввести в поле поиска и добавить кнопкой Add by name. На серверах без
доступной агрегации список явно помечается как значения только загруженной страницы;
ручной ввод точного имени продолжает работать.

Используется read-only `POST /search/aggregate` из
[Search Scripting API](https://go2docs.graylog.org/current/making_sense_of_your_log_data/simple_search_scripting_api.htm)
с абсолютным временем, stream, группировкой по настроенному Service field и count.
При HTTP 404/405 пробуется legacy `/search/universal/absolute/terms`; ошибки прав
не скрываются повторным запросом к другому endpoint. Сам список не требует CSV-экспорта.
Сохранённые поиски включают выбранный фильтр; Follow request снимает sources,
чтобы показать весь запрос по всем сервисам.

Строка запроса предлагает имена полей при вводе или по Ctrl+Space. Список включает
стандартные поля Graylog, поля настроенного профиля и поля полученных сообщений.
Для `level:` доступны числовые уровни с расшифровкой; для `source`, поля сервиса,
`application`, `stage`, `channel` и `facility` — значения из полученных событий.
Tab/Enter вставляет выбранную подсказку, стрелки перемещают выделение, Escape
закрывает список. Ctrl+Enter запускает поиск. Подстановка заменяет только текущий
токен; текст в кавычках остаётся без изменений. Примеры синтаксиса есть в подсказке
самого поля: `level:3 AND source:api`, `level:[0 TO 3]`.

В правом инспекторе находятся уровень, сообщение, команды события и вкладки
Fields/Stack trace/JSON/Exception text. Stack trace содержит навигационный список
локальных файлов и строк с каталогами (относительно проекта, если возможно), настройки mappings и строку
сопоставления удалённого пути локальному. Полный текст цепочки исключений находится
в отдельной вкладке Exception text. Для несопоставленного пути показано предупреждение;
проверка существования файла выполняется при переходе. До выбора строки отображается
подсказка. У таблиц и текстовых областей нет вложенных рамок. Статус поиска расположен
под таблицей, состояние индекса — в нижней строке.

У каждой строки лога есть узкая цветная полоса источника слева и маркер тем же цветом
у имени сервиса. Цвет определяется значением колонки Service и сохраняется между
страницами и сессиями, независимо от уровня события. Уровни ERROR/WARN выделены
цветом текста в своей колонке. Контекстное меню строки позволяет выбрать цвет
источника или вернуть автоматический. Общие настройки цветов находятся во вкладке
Source colors; изменение цвета не перезапускает поиск и индекс.
Полоска отделена от границы ячейки и соседних строк отступами и имеет скруглённые края.

- Несколько подключений с добавлением, редактированием и удалением.
- Дерево streams, доступных текущему пользователю; поиск по всем доступным сообщениям.
- Поисковые выражения Graylog, периоды 5/15 минут, час и сутки.
- Страницы по 100/250/500 событий. При переходе между страницами временные границы
  сохраняются. Максимум — первые 10 000 результатов.
- Live: обновление последних сообщений, пока окно видно. Каждые 5 секунд плагин
  проверяет готовность поиска и индекса исключений, затем начинает новый цикл.
  Длительный сбор не отменяется каждым тиком. Ошибка поиска или индекса останавливает Live.
- Все поля события, исходный JSON, stack trace и выделение уровней.
- **Follow request**: поиск по `request_id`, `trace_id` или `correlation_id`
  среди всех доступных streams текущего подключения.
- **Show logs around**: сообщения в пределах пяти минут до и после выбранного
  события, в текущем stream, с очисткой текстового запроса.
- Переход из stack trace в локальный исходник, двойным кликом или кнопкой
  **Open in Editor**.
- Сохранение текущего поиска в дереве. Кнопка удаления удаляет выделенный
  сохранённый поиск либо выбранное подключение.
- Контекстное меню редактора **Search in Graylog** для выделенного текста.
- **Open Graylog** открывает выбранное событие по ссылке `/messages/{index}/{id}`.
  Если в примере из полного индекса нет имени индекса, открывается поиск по точному
  `_id` в том же временном диапазоне. Без выделенного события кнопка недоступна.
  Используется Web URL подключения с сохранением префикса reverse proxy;
  авторизация выполняется в браузере, токен API в ссылку не добавляется.

Время в таблице показано в UTC. Колонка сервиса настраивается в
**Settings → Tools → Graylog Explorer → Project settings → Service**.
Значение по умолчанию — `source`; предусмотрены
резервные варианты `service_name`, `service`, `application_name`, `application`.

## Настройки IDE и проекта

**Settings → Tools → Graylog Explorer** содержит общие настройки всех проектов:

| Вкладка | Параметры |
| --- | --- |
| Connections | Серверы, API/Web URL, токены в Password Safe, проверка подключения |
| Search and updates | Подключение по умолчанию, начальные период и размер страницы, Live при открытии, интервал обновления, автоматический индекс исключений, число примеров на позицию |
| Highlighting | Подсветка по умолчанию, сообщения рядом со строками кода, значки gutter, полоса ошибок редактора, обычный и выбранный фон для светлой и тёмной темы |
| Source colors | Цветные маркеры источников в таблице, цвета для конкретных имён сервисов и возврат автоматических цветов |
| Network | Таймаут подключения, таймаут запроса, размер пакета scroll-экспорта |

Вложенная страница **Project settings** сохраняется в `.idea/workspace.xml` текущего
проекта. Здесь задаются предпочтительное подключение, включение подсветки для
проекта, несколько сопоставлений путей и имена полей сервиса, типа и объекта
исключения, файла, строки, stack trace, request ID и trace ID. Вложенные имена,
например `context.request_id`, поддерживаются в JSON и в полном индексе исключений.
Исходный JSON события сохраняется без изменений.

Формы настроек используют компоненты IntelliJ Platform: `ToolbarDecorator` для
списков подключений, mappings и цветов источников, `OnePixelSplitter` для списка
и сведений о сервере, `TitledSeparator` для групп параметров и `ColorPanel` для
цветов подсветки. Сведения о сервере показаны обычным UI-шрифтом; URL можно выделить
и скопировать. В колонке локального корня доступен системный диалог выбора каталога.
Форма проекта прокручивается самим окном Settings, без дополнительной прокрутки
вокруг всей формы. На профиле проекта не показывается неактивное переопределение
подключения; при выборе сервера наследуемые поля остаются недоступными до включения
Customize.

Оформление сверено с рекомендациями JetBrains по
[спискам и панелям действий](https://plugins.jetbrains.com/docs/intellij/lists-and-trees.html),
[компоновке](https://plugins.jetbrains.com/docs/intellij/layout.html),
[группировке](https://plugins.jetbrains.com/docs/intellij/groups-of-controls.html),
[типографике](https://plugins.jetbrains.com/docs/intellij/typography.html) и
[встраиванию форм Settings](https://plugins.jetbrains.com/docs/intellij/settings-guide.html).

Профиль **Project defaults (all connections)** применяется ко всем подключениям
этого проекта. Для отдельного сервера можно включить **Customize this connection
for this project**. Отключение переопределения возвращает профиль проекта.
Пустой локальный корень означает каталог открытого проекта; при нескольких
сопоставлениях выбирается самый длинный подходящий удалённый префикс.

Серверы общие: изменение или удаление подключения применяется во всех проектах.
Пути и поля одного проекта не меняют другой. Начальные период и размер страницы
используются, пока в проекте нет запомненной выборки; после поиска сохраняются
последние значения. Переключатель **Code marks** в окне задаёт переопределение
подсветки для проекта; вернуть наследование можно через **Use IDE default**.
При отключённом автоматическом индексе **Refresh marks** запускает его вручную.
Лимит примеров ограничивает только сохранённые события, полный счётчик не обрезается.

**Apply/OK** сохраняют настройки, **Cancel** отбрасывает черновик, включая введённые
токены. Применённые изменения подхватывает открытый Explorer; индексы перестраиваются
с новым форматом и путями. Кнопка с шестерёнкой в Explorer открывает эту страницу.

При первом запуске версии 0.4 подключения из версий 0.1–0.3 автоматически переносятся
на уровень IDE с сохранением ссылок на Password Safe. Старые пути и поле сервиса
становятся профилями соответствующего проекта; сохранённые поиски остаются на месте.
Проекты мигрируют при открытии. Для сохранности доступа ещё не открытых проектов
старые записи Password Safe могут сохраняться после смены токена.

## Переход в исходники

### Подсветка исключений

Плагин связывает найденные события с исходниками. Отдельный фоновый индекс учитывает
**все распознанные исключения за выбранный период с текущим запросом и stream**,
включая события за пределами открытой страницы и первых 10 000 сообщений.
После полного сбора у мест возникновения появляются фоновые выделения и метки
Graylog. Файлы подсвечиваются и при последующем открытии в редакторе. Подсказка
метки содержит типы исключений, полный счётчик для позиции, подключение и границы периода.

- Выбранное событие выделяется более заметным фоном. **Open in Editor** открывает
  и выделяет выбранный фрейм stack trace.
- В PHP для **выбранного события** плагин может показать значение сразу после
  аргумента: `$raw` + временная подсказка ` = "+12025550123" · Graylog`.
  Имя переменной не фиксировано: подходят `$input`, `$phone` и другие имена.
  Привязка проверяется по PHP PSI: точный класс и строка возникновения из цепочки
  исключений, `throw new ExceptionClass($variable)` и конструктор с
  `parent::__construct(sprintf('literal %s', $parameter))`. Поддерживается один
  строковый параметр без преобразований; конструкторы родителей не должны менять
  сообщение. Анализ выполняется в фоне после индексации IDE, код не запускается.
- Если доказать такую связь нельзя, после строки остаётся сообщение исключения:
  `throw new PhoneNumberInvalidException($raw);  Graylog: Invalid phone: +12025550123`.
  У каждого звена цепочки собственное сообщение. Без выбора события берётся один из
  примеров; при нескольких событиях рядом указан полный счётчик. В gutter доступно
  до трёх различных сообщений. Значение выбранного события используется даже если
  оно не вошло в ограниченный список примеров позиции.
- Подсказки — разметка редактора, исходник не меняется. Это записанное в логе
  строковое представление аргумента, а не живое состояние отладчика. Оно не
  распространяется на другие использования или одноимённые переменные. При
  редактировании исходника подсказки значений удаляются; для изменённого несохранённого
  файла или конструктора привязка не строится. Версия исходников должна соответствовать
  версии сервиса из лога: плагин пока не проверяет commit/hash развёрнутого кода.
  Сложные выражения, именованные аргументы, несколько подходящих вызовов на строке,
  изменяемый параметр и неоднозначный шаблон дают обычное сообщение у строки.
  Настройки: **Settings → Tools → Graylog Explorer → Highlighting**:
  **Show exception messages next to source lines** управляет всеми подсказками,
  **Show selected log values beside PHP variables…** — значениями у переменных.
  Адаптер PHP подключается только при наличии PHP-плагина; без него сохраняются
  сообщения у строк и все остальные возможности Explorer.
- Клик по метке показывает до **20 примеров** по умолчанию для строки и приостанавливает Live.
  Полный счётчик сохраняется независимо от числа примеров. **All loaded events**
  возвращает исходную страницу таблицы. Примеры содержат поля, выбранные для экспорта;
  обычные страницы таблицы получают полные JSON-события.
- **Code marks** отключает подсветку и отменяет незавершённый сбор. Повторное
  включение запускает сбор заново; настройка сохраняется в workspace.
- Переход между страницами и изменение размера страницы сохраняют индекс периода.
  Смена запроса, периода, подключения или stream отменяет старый сбор и очищает метки.
  Плагин удаляет только собственную разметку редактора.

Внизу окна показано состояние индекса, число просмотренных сообщений и итоговая
статистика. **Cancel scan** отменяет сбор, **Retry marks** повторяет его после
ошибки, **Refresh marks** обновляет готовый индекс для того же временного интервала.
Новый поиск фиксирует новые границы относительного периода.

Для полного прохода используется потоковый CSV scroll-экспорт Graylog с `limit=0`,
без ограничения окна JSON-пагинации. Вложенные объекты `exception`, которые CSV
представляет строками, восстанавливаются через JSON API по ID сообщения. Индекс
публикуется целиком после чтения экспорта, проверки эффективных временных границ
и сопоставления числа сообщений с результатом поиска. Если сервер обрезал период,
экспорт оборван или данные изменились во время сбора, отображается
**Period index incomplete**, без публикации неполных счётчиков. Можно повторить сбор.
В памяти сохраняются счётчики по позициям и настраиваемое число примеров, а не весь поток сообщений.

Сопоставление использует `exception_file` / `exception_line`, вложенные поля
`exception.file` / `exception.line`, затем stack trace. Обычные `file` / `line`
используются как резервный вариант при наличии признаков исключения: они часто
обозначают место вызова логгера. Поддерживаются поля типов `exception_class`,
`exception_type`, вложенные `exception.class` / `exception.type` и имена из trace.

Поддерживается формат Yii: `ctxt_exception` автоматически распознаётся как объект
исключения, даже если его значение — JSON-строка. Для другого имени поля применяется
настройка **Exception object field**. Вкладка Exception text показывает тип, сообщение,
код, место возникновения и фреймы, а цепочки `previous` / `cause` разделяет заголовками
**Caused by**. Поддерживаются `file` вида `/application/path.php:59`, массивы строк
и массивы объектов фреймов. Повторяющиеся фреймы сохраняются в тексте trace.
Исходное представление остаётся доступным во вкладке JSON.

Каждое звено цепочки получает метку у своего места возникновения. Например,
`UserError` и его `previous: PhoneInvalidException` подсвечивают две строки,
но итоговый счётчик exception events увеличивается на одно событие лога.
Если несколько звеньев возникли на одной строке, событие учитывается там один раз,
а подсказка содержит все типы. Клик по любой из меток открывает то же событие
с полной цепочкой. Резервный разбор обычного текста не пересекает границы JSON-строк.

Группировка выполняется по файлу и строке. Один класс исключения в разных местах
получает разные метки; разные типы на одной строке объединяются в одной метке.
Без исходной позиции событие остаётся доступным в таблице, без метки в редакторе.
Позиции берутся из логов; соответствие локальной версии кода серверному релизу
автоматически не проверяется.

### Настройка путей

В **Settings → Tools → Graylog Explorer → Project settings** задаются:

```text
Remote source root: /application
Local source root:  /home/user/project/back
```

Тогда `/application/src/StockClient.php:87` открывает
`/home/user/project/back/src/StockClient.php` на строке 87. По умолчанию локальный
корень совпадает с открытым проектом. Поддерживаются ссылки вида `file.php:87`
и `file.php(87)`, а также отдельные поля `file` / `line`. Пути с выходом за
настроенный корень отклоняются.

## Сборка без сети

Нужны Python 3.9+ и установленный PhpStorm / IntelliJ IDEA 2026.3 с JDK 25.
Скрипт автоматически ищет PhpStorm и IDEA в стандартном каталоге Toolbox под Linux.
Можно указать путь явно:

```bash
python3 build.py --ide-home /path/to/phpstorm
```

Для сборки требуется установленный PhpStorm SDK: из него берётся compile-only API
опционального PHP-адаптера. PHP API не включается в ZIP.
Сборка компилирует Java-код против библиотек локальной IDE, запускает контрактные
HTTP-тесты на loopback и создаёт установочный ZIP. Зависимости не скачиваются.
JDK берётся из IDE либо `JAVA_HOME`. Для сборки без тестов есть `--skip-tests`.

Альтернативная сборка Gradle:

```bash
export IDE_HOME=/path/to/phpstorm
export JAVA_HOME="$IDE_HOME/jbr"
./gradlew buildPlugin
```

Первый запуск wrapper скачивает Gradle 9.3.0, если его нет в кеше.
Gradle использует обычный Java plugin и локальный SDK: `buildPlugin` упаковывает
JAR в стандартную структуру ZIP JetBrains. В этой версии нет загрузки SDK,
инструментации форм и автоматического запуска Plugin Verifier.

## Локальная демонстрация

```bash
python3 scripts/mock_graylog.py --demo-project /tmp/graylog-demo
```

Открыть `/tmp/graylog-demo` в IDE и добавить подключение:

```text
Name:              Demo
API URL:           http://127.0.0.1:19000/api
Access token:      demo-token
```

В Project settings оставить удалённый корень `/application` и пустой локальный
корень, если открыт `/tmp/graylog-demo`.

Запрос `request_id:"abc-123"` покажет цепочку оформления заказа.
В mock server реализованы простые текстовые запросы и точное сравнение поля;
полный язык запросов доступен на реальном Graylog. Web UI у mock server отсутствует.
Для демонстрации исключения за пределами первой страницы добавьте `--extra-events 120`:
в окне будет 127 сообщений и две позиции исключений, одна из которых отсутствует
на первой странице из 100 событий.
Флаг `--yii-event` добавляет пример Yii с цепочкой исключений и демонстрационные
исходники для обоих мест возникновения; запрос `message:"Invalid phone number."`
показывает это событие отдельно.

## Проверки и границы версии

`python3 build.py` запускает тесты HTTP Basic, URL с префиксом, передачи Unicode
и специальных символов в запросе, streams, пагинации, HTTP-ошибок, запрета
редиректов, отмены запроса, разбора событий и сопоставления путей.
Тесты полного индекса проходят поток из 12 037 сообщений с одинаковым временем,
проверяют счётчики и ограничение примеров, восстановление вложенных исключений,
отмену заблокированного чтения и отказ от неполного или ограниченного сервером экспорта.
Также проверяются миграция старого состояния, наследование профилей, отдельная
XML-сериализация областей, валидация параметров, вложенные имена полей и их
восстановление при CSV-экспорте, применение лимита примеров и размера пакета.

UI-проверка под Linux с Xvfb:

```bash
python3 scripts/smoke_test.py --ide-home /path/to/phpstorm --theme light
python3 scripts/smoke_test.py --ide-home /path/to/phpstorm --theme dark
```

Скрипт запускает отдельный экземпляр IDE с собственными настройками, приватным
виртуальным дисплеем и локальным mock API. Проверяет загрузку окна, авторизацию
через Password Safe, получение streams и событий, переход на строку PHP-файла.
Тестовый startup hook добавляется только во временный JAR; в установочный ZIP
он не входит. Отчёты и снимки экрана находятся в `build/reports/smoke/light/`
и `build/reports/smoke/dark/`. В каждом каталоге есть `explorer-fields.png`,
`explorer-stack.png`, `explorer-json.png` и `explorer-exception-text.png` с нативными
вкладками и панелями действий. `tree-focused.png` / `tree-unfocused.png` показывают
два состояния выделения, `query-completion.png` / `query-level-values.png` — подсказки.
Отчёт `ui-details-result.txt` проверяет вставку по Tab, закрытие по Escape, разделение
trace/текста, локальный mapping и цвет источника на выбранной/невыбранной строке.
Сценарий вызывает команды через реальные ActionToolbar и проверяет оба оформления.
Поиск в дереве проверяется отдельно от запроса логов: выборка и индекс сохраняются,
очистка фильтра возвращает выделение активного stream. Через нативное меню меняется
размер страницы; проверяется сохранение того же индекса и восстановление инспектора
после снятия и возврата выделения события.
Проверка включает метку исключения, различие обычной и выбранной подсветки,
переход к связанным логам по клику, возврат выборки, переключение и очистку меток.
В сценарии 128 сообщений: таблица показывает страницу из 100 строк, а индекс — три
события исключений в пяти позициях, включая событие со второй страницы и
цепочку Yii. Проверяется сохранение того же индекса при переходе вперёд и назад.
Отдельный поиск Yii проверяет читаемый trace, восстановление через CSV/JSON,
три места возникновения при одном событии, переход к причине на строку 46,
сообщение с фактическим номером в inline-подсказке и метке gutter. Проверяются
отключение подсказок, сохранность чужих inlay-элементов и неизменность исходного текста.
Снимок и отчёт: `yii-stack-trace.png`, `yii-result.txt`.
Настройки проверяются в настоящем диалоге IDE: расположение обеих страниц,
Apply/Reset/Cancel, черновики токенов и Password Safe, проверка соединения,
валидация полей и цветов, профили и обновление уже открытого Explorer.
Снимки страниц: `settings-ide.png`, `settings-project.png`; отчёт:
`settings-result.txt` в том же каталоге.

Плагин использует `GET /api/streams`, `GET /api/search/universal/absolute` для таблицы
и чтения JSON, а также `GET /api/search/universal/absolute/export` для полного индекса.
Для списка источников используется `POST /api/search/aggregate`; на старых серверах
пробуется `GET /api/search/universal/absolute/terms`. У пользователя должны быть
права агрегации по выбранным streams; при их отсутствии остаются ручные фильтры.
Пользователю нужны права чтения streams и `searches:absolute`. Наличие API и права
зависят от сервера. SSO-вход в браузере не заменяет access token; редиректы API
не выполняются. Нестандартные сертификаты нужно добавить в доверенные сертификаты
JVM, проверка TLS не отключается.

Подсказки запросов покрывают имена полей и отдельные значения, а не всю грамматику
Lucene. В этой версии нет серверных dashboards/alerts,
редактирования streams и сохранения больших выгрузок пользователем в файл. Совместимость ограничена
веткой IDE 2026.3; другие версии требуют отдельной проверки.
